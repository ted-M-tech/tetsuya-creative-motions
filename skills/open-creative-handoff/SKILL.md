---
name: open-creative-handoff
description: Publish an existing creative work as a reusable portfolio case with prompts, decisions, runnable source and asset provenance. Use when the user explicitly wants to share how a website, slide deck or film was made.
---

1. Inspect the finished artifact and identify its actual source revision. Preserve existing work and publication routes.
2. Separate three deliverables: the work, the explanation, and the reproducible package.
3. Curate user-authorized prompt excerpts. Label reconstructed prompts as reconstructed; never invent missing historical messages or expose private handoffs.
4. Explain the decisions that changed the result: friction, change, reason, observable verification.
5. Export the smallest runnable source with a lockfile and commands. Exclude credentials, account data, raw voices, private identifiers and unrelated backend code.
6. Record upstream revision, asset origins, license boundaries, dependency versions and known limits. Do not promise identical AI output from a prompt.
7. Present actual work previews. Use one project with related formats, not inflated project counts. Keep historical product claims in context.
8. Verify desktop, mobile, keyboard, reduced motion, downloads, source links and published URLs. Publish only within the user's authorized scope and keep a concise release receipt.
