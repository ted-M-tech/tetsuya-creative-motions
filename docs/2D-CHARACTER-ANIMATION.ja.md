# 2Dキャラクターアニメ制作ガイド

[English](2D-CHARACTER-ANIMATION.md) · **日本語**

承認済みの2Dキャラクターを、その絵柄のまま動かしてショート動画にする手順です。Mimi（Lanclo）の「自分の声、むり」で通した流れをまとめています。記録は [films/mimi-jibun-no-koe](../films/mimi-jibun-no-koe/PROCESS.md)、そのまま渡せる指示は [PROMPT.md](../films/mimi-jibun-no-koe/PROMPT.md)。3Dの手順は [3Dキャラクター制作ガイド](3D-CHARACTER-WORKFLOW.ja.md)。

## 2Dと3Dの使い分け

| | 2D（このガイド） | 3D |
|---|---|---|
| 向いている | 表情と感情、ブランドの絵柄そのまま、短いショートの量産、アプリでの再利用（Rive） | 振り向き、カメラの回り込み、立体の空間 |
| Mimiでの判断 | 同じ3ポーズを3D・3Dトゥーン・2Dで比べ、依頼者が2Dを「明らかに一番」と判断 | 正本は残し、回り込みが要る回と参照に使う |

Duolingoもアプリ内のキャラクターは2DのRive。3Dは2Dに見せるために使っている。

## 道具

| 道具 | 役割 | 入れ方 |
|---|---|---|
| Rive CLI | 骨で動かす2Dアニメ、1コマずつの書き出し | `brew install --cask rive-app/tap/rive-cli`、`rive update`。書式はAIの学習より新しいので `rive docs` / `rive schema` を引く |
| Codex（`codex-p`） | 公式の絵柄でポーズ・表情・背景を描く、レビュー | `codex-p exec --image a.png,b.png - < prompt.txt` |
| HyperFrames | カメラ、字幕、UI、効果、締めの合成と書き出し | Claudeは hyperframes 系スキル、Codexは公式プラグイン |
| ffmpeg / ImageMagick / Python | 切り抜き、連番の動画化、音のミックス | `brew install ffmpeg imagemagick`、`uv` |

外部のRive用スキルは小規模でキャラクター向けではないため入れていない。

## 手順

1. **話と冒頭**：最初の1秒に感情のピークと自分ごとの問い。ストーリーの節目（問題→体験→結果→練習→評価→締め）を秒数つきの表にする。
2. **絵コンテ**：3D正本があれば3Dプリビズ、なければ仮の絵でアニマティック。本物の声を当てて別のAIにレビューさせる。
3. **ポーズを描く**：画像生成AIに公式PNGと既に描いたポーズを毎回添付。同じ線・色・頭身・小物の向き・同じ斜めの向き・同じ縮尺・白背景・文字なし、を明記。公式イラストで足りるポーズはそれを使う。
4. **切り抜く**：白背景を四隅から塗りつぶして透明化、余白をトリム。口パク用の2枚は**同じ範囲**で切る。
5. **大きさをそろえる**：耳や腕の伸びで絵の高さが変わるので、頭の大きさが同じに見えるよう拡大率を決め、足を同じ位置に置く。ポーズを全部並べたシートで確認。
6. **リグ**：絵を格子＋ドロネーの網にし、位置からウェイト、5本の骨（頭・耳・左右の手・接地）。演技は骨のキーで（揺れ、伸び、しぼみ、弾み、跳躍、うなずき）。全身の動きは頭と接地の骨を一緒に動かし、潰れ・伸びは頭の骨だけ上下させる。
7. **口パク**：口を開けた絵を同じ網に重ね、声の音節の山（周囲より大きい瞬間）でだけ表示。
8. **書き出し**：`rive <dir> --screenshot=f###.png --advance=N` をコマごとに（並列で）。背景も絵の中に入れる。
9. **合成**：HyperFramesで全カットを1つのカメラ枠の中に並べ、寄りはその枠に付ける。字幕・UI・ラベル・効果・締めを重ねる。
10. **音**：声、コードで作る効果音、軽いBGM（声の間は下げる）。商品の証拠になる声に効果音を重ねない。
11. **確認**：`npx hyperframes check`、主要なコマ、長さ・解像度、最後に別のAIのレビュー（SHIP判定）。音は通しで聴く。

## Riveの落とし穴

- **先に書いた要素が手前**に描かれる（HTML / SVGと逆）。背景は最後に書く。
- `--screenshot` は1回の呼び出しで1コマ。複数の `--advance` を並べても最後の1枚だけ。
- 書き出しは不透明。透明背景のオプションはない。
- 不透明度のキーは property 18、骨の回転は15、位置は90 / 91。

## シリーズにするとき：共通キット

2本目からは前の作品を写さず、キットから始める。Mimiは [kits/mimi-short](../kits/mimi-short/README.md)：キャラクターのライブラリの写し（正本は製品側のリポジトリ）、`add_pose()` / `lipsync()` / `build_shots()` を足したリグ、音のキット、共通のCSS/JS。作品は新しい絵、その回の演技、合図の表、編集だけを持つ（[films/mimi-think-sink](../films/mimi-think-sink/PROCESS.md)）。

- 小道具はRiveでなく編集で動かす。書き出しを待たずに何度でも直せる。
- 言い間違いネタのTTSは文字起こしで確認できない（モデルが正しい文に寄せる）。人の耳で確かめる。
- `xargs -I` は255バイトまで。長いパスは環境変数で渡す。

## 実際のアプリを見せるとき

製品をシミュレーターで、QA用のデモデータ（個人データなし、毎回同じ画面）で動かし、UIテストで機能を操作しながら `simctl io recordVideo` で録る。録画は可変フレームレートなので、60 fpsにそろえてから切る。キャラクターはページと同じ色の平らな背景で書き出して縮小し、スマホの枠の横に置く。枠には時刻を付けず、中の動画だけに付ける。画面の文字はスマホでは読めないので、伝えたい1点は寄りと大きなカードで出す。QA用デモデータは2回目の操作（録り直しなど）に対応していないことがあるので、録画の前に使える範囲を確かめて話を組む。デモデータの文字は編集で隠す。例：[films/mimi-shashin](../films/mimi-shashin/PROCESS.md)、[films/mimi-daily](../films/mimi-daily/PROCESS.md)。

## 画面づくりの決まり

- 字幕は上部、白い角丸。下端約400 pxはSNSのボタン用に空ける。
- 端末の中のUIは雰囲気。意味は端末の外の大きなラベルで伝える。
- カードやラベルはキャラクターの顔を隠さない。
- デモの値を見せるときの表記は依頼者の判断（Mimiのショートでは「デモ表示」不要）。

## 記録の残し方

作品ごとに `films/<id>/` に、完成形の統合プロンプト、制作過程（依頼者の指示・AIへのプロンプト・レビュー・判断）、プロンプトとレビューの原文、途中経過の画像、ソースと書き出し手順、素材の権利を残す（[作品を追加する](ADDING-A-FILM.md)）。
