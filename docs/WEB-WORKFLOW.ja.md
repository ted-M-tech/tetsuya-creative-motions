# LP・Web制作の標準

2026-10-07採用。対象は新規のLP・作品集・制作ノート。既存サイトは改修範囲に合わせて維持し、全面移行を前提にしません。統一するのは制作工程と記録で、全作品の見た目ではありません。

## 技術の標準

| 層 | 標準 | 例外の判断 |
|---|---|---|
| ページ・共通部品 | Astro、静的出力 | 既存React/ViteやHTMLを小修正のためだけに移行しない |
| データ・処理 | TypeScript strict | 外部データは実行時にも検証する |
| スタイル | CSS、共通トークン、部品単位のスタイル | 既存Tailwindは維持可。新規導入は具体的な利点がある場合 |
| 制作ノート | Markdown、増えるコンテンツはContent Collections | MDXは本文内で部品が必要な場合のみ |
| 動き | CSS・小さなブラウザJS | 複雑な操作はReact/TSX island。読込タイミングを明示 |
| 公開 | HTML/CSS/JS/画像の静的配信 | 認証・課金・APIは別の必要性として設計 |

JavaScriptの配信量と運用費は別問題です。React/Viteにも静的配信が可能です。Astroはコンテンツ主体の新作の既定値であり、万能な優劣ではありません。常時稼働サーバー、有料CMS、生成APIをLPの必須条件にしません。無料枠・ファイル上限は公開時のサービス条件を確認します。制作時のAI利用料・ドメイン代は配信費に含めません。

## デザインスキル

| スキル | 採用する役割 | 適用の仕方 |
|---|---|---|
| [Impeccable](https://github.com/pbakaus/impeccable) | 主な設計・整理・仕上げ | 構成、情報階層、必要に応じたdistill/adapt/audit/polish。全部を毎回実行しない |
| [Taste Skill](https://github.com/Leonxlnx/taste-skill) | 別案・批評 | 題材に合った独自性を検討。Impeccableと無条件に重ねない |
| [Tetsuya Creative Web](../skills/tetsuya-creative-web/SKILL.md) | この制作工程・公開記録 | 技術選択、製品事実、再現情報をつなぐ |

Taste Skillのローカル名は `design-taste-frontend`。配布元のReact/Next.js等の既定値は、このAstro標準より優先しません。スキルはデザイン判断の支援で、サイトの実行依存ではありません。承認済みブランドとユーザーの要望を優先します。

**実際のLanclo制作：Taste Skillで初期案・批評 → 比較 → Impeccable案を選択・改良。** [使用記録](../projects/lanclo-lp/SKILLS.md)。他の過去作品で使用記録がないスキルを、後から「使用済み」にしません。

## 制作の順序

1. **事実と目的。** 誰が、何を理解し、どう行動するページか。現行実装、ブランド、出典、未実装の予定を整理する。
2. **構成。** 一番伝える価値、実物・デモ、必要な根拠、行動導線を決める。全LPに同じセクション数や並びを強制しない。
3. **表現。** タイポグラフィ、余白、素材、色、動きの役割をDESIGN.mdへ。見せ場から作り、意味のない補足や同じ画像の反復を減らす。
4. **実装。** ページ、部品、コンテンツを分離。動きが無効でも説明は読める。画像サイズを指定し、動画はポスターと読込方針を持つ。
5. **検証。** 型チェック・ビルド、モバイル/ノートPCで改行と横溢れ、リンク、キーボード、reduced motionを確認。自動指標と実表示の両方を見る。
6. **公開と記録。** ソースcommit、lockfile、使用スキル、素材、実行コマンド、検証結果、公開先を固定。対象の公開権限と既存公開担当の運用に従う。

Astroの通常のゲートは `astro check && astro build`。実際のpackage.jsonにcheck/buildスクリプトを置き、READMEにはそのプロジェクトで動作確認したコマンドを書く。新規プロジェクトのNodeとパッケージマネージャーは採用時の対応版を固定する。

## 再現性の3段階

- **同じ実装を動かす：** 固定commit/tag、lockfile、ランタイム、ビルド手順、必要素材が揃う。
- **同じ工程を追う：** 原文の指示・修正、判断理由、適用スキルとモデルの記録がある。
- **別の題材へ応用する：** 再構成したプロンプトと差し替える変数が明確。

AIへの同じ指示から同じピクセルが出るとは保証しません。原文と再構成プロンプトを分け、スキルの「導入済み」「参照した」「その工程で使った」「最終版に採用」を区別します。

新作では [制作記録テンプレート](../templates/web/REPRODUCTION.md) と [スキル記録テンプレート](../templates/web/skills.lock.example.json) を使います。参照したスキルはupstream commitとローカル差分の有無を記録。正確なcommitが不明ならnullとし、実際に読んだファイル群のSHA-256と取得時点を残します。後日取得した最新版を当時の版として記録しません。再配布できるスキルの保存はライセンス確認後に限ります。

## はじめるための指示

```text
$tetsuya-creative-web で、この製品のLPを制作してください。
目的・対象者・製品の現行仕様は添付のBRIEFを根拠にしてください。
新規実装はAstro＋TypeScript strict＋CSS、静的出力を標準に。
Impeccableを主なデザイン支援にし、Taste Skillは別案が必要な場合に使ってください。
承認済みブランドと参考資料を踏まえ、構成→実装→スマホ/PC確認まで進めてください。
作品とともに使用スキルの版、プロンプト、設計判断、素材出典、再現コマンドを残してください。
原文がない指示は再構成と明記してください。公開はこのプロジェクトの承認範囲に従ってください。
```

公開スキルの導入例（このリポジトリのルートから）：

```sh
mkdir -p "${CODEX_HOME:-$HOME/.codex}/skills"
cp -R skills/tetsuya-creative-web "${CODEX_HOME:-$HOME/.codex}/skills/"
```

ImpeccableとTaste Skillは各公式リポジトリの導入方法を使用してください。このスキルには第三者スキル本体を同梱していません。導入時の版と実際に使用した版を分けて記録します。
