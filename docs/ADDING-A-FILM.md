# 作品を追加する

1. templates/film/をfilms/作品ID/へコピー。
2. 完成形のPROMPT.md、NARRATION.md、CREDITS.mdと編集ソースを保存。
3. site/posters/に軽いJPGサムネイルを追加。
4. films/catalog.json、ルートREADMEの作品カード、site/index.htmlに追加。
5. MP4はsite/media/または配信先へ。Gitには入れない。
6. npm run check とスマホ幅・PC幅での再生確認を行う。

作品を増やす際も、制作途中の全ログではなく、読者が再利用できる最終判断を残します。実際の入力と後から統合したプロンプトは区別してください。

## すべての作品を再現できるように残す（2026-10-20〜）

完成した作品は、別の人やエージェントが同じものを作り直せる状態で `films/<id>/` に残す。最低限そろえるもの：

- `README.md`（英語）/ `README.ja.md`：何の作品か、尺・解像度・手法、ファイル案内、再現の入口
- `PROMPT.md`：完成形を作り直すための統合プロンプト（最初の入力の原文ではないと明記）
- `PROCESS.md`：制作過程。依頼者の指示（原文の引用）、AIに渡したプロンプト、レビューと採否、途中の判断、学んだこと
- `prompts/`：生成やレビューに使ったプロンプトの原文
- `reviews/`：レビューの原文（失われたものは要約と明記）
- `process/`：途中経過と完成の画像（軽いJPG）
- `source/`：スクリプト・素材・書き出し手順の `README.md`。Gitに入れない素材（声、完成MP4、フォント）は置き場所と取得方法を書く
- `CREDITS.md`：素材の出典と権利

正本が別のリポジトリにある場合（例：キャラクターの3D正本はLancloの `design/`）は、場所を明記し、ここには公開用の写しを置く。新しい作り方を通したら `docs/` の汎用ガイドとスキルの参照も更新する（[2D](2D-CHARACTER-ANIMATION.ja.md)、[3D](3D-CHARACTER-WORKFLOW.ja.md)）。

## 作品と更新版の扱い

作品一覧は企画・プロジェクト単位で1件。改訂版は同じ作品の完成動画を更新し、以前の版は制作ノート内の「制作の変遷」に残す。声や表現を変えた実験は「番外編」にまとめる。カタログのトップレベルは作品のみ、番外編はextras、旧版はhistoryに記録する。異なる企画・目的の映像を作ったときに、新しい作品として追加する。

作品フォルダは `films/<project>/` を固定の入口にする。最新版の台本・プロンプト・sourceを直下に置き、旧版は `history/<version>/`、番外編は `extras/<name>/` へ。作品名の末尾に版名を付けたトップレベルフォルダを増やさない。カタログのpathは制作資料の場所、posterとmediaは配信用ファイル名。既存の公開URL・MP4名は無理に変更しない。

## 日本語・英語

一覧と制作ノートは日本語URLと`/en/`の対応ページを更新し、ヘッダーから相互リンクする。各ページのlang、canonical、hreflang、sitemapも更新する。GitHubは英語をデフォルトのREADME.md、日本語をREADME.ja.mdに置き、相互リンクする。作品紹介・制作判断は翻訳し、台本・生成入力の原文は翻訳版で置き換えない。英語ページで原文の言語を明記する。
