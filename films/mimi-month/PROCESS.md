# 制作の経緯

Notion Content Calendar ID 36（Drive「036. Watched by Mimi for a Month」）。オーナーの言葉（原文、コーディネーター経由）：

> 2,3,6,7,8,9,11,12 作成で

承認された企画（コーディネーターの要約）：フック「Mimiに1ヶ月見張られた結果」。Mimiの毎日のまとめが1ヶ月（1日目→30日目）でどう変わるかのタイムラプス。学習者に合わせてアドバイスが変わっていく様子。#24（Mimiはずっと見てる、ホラー調）と重ならないよう、明るく笑える方向に。必要なら日ごとの現実的なフィクスチャデータ（撮影用パッチのみ、アプリは変えない）を使い、例のデータであることを画面に出す。

## アプリで確かめたこと（Lanclo origin/main 5998d20d、native-ios が正）

- Mimiのまとめ（`Views/MimiReportView.swift`、`Views/MimiReportHeader.swift`、`Core/MimiDailyReport.swift`、`docs/features/mimi-ai.md`）：
  - 1日1回、練習リマインダーの時刻（初期20:00）に、直近7日の日記と練習から。タイトル「◯月◯日(曜)のまとめ」、期間と次回の時刻。
  - ボキャブラリー：決まった言い回し（`MimiPhraseCatalog` の “And then”、“I think”、“very”、“good” など）が2件以上の日記で3回以上、と日記の書き換え。発音：レッスンプランのランキング（今週の回数）。今週出ていない癖は出ない。
  - 癖がなく記録はある日：「いい調子！この7日間は目立つ癖はなかったよ。記録を続けてくれたら、また見つけるね。」
  - 最初のレッスン後の最初のレポート：「最初のレポートだよ。まずは今日の練習で気づいたポイント。…」「今日の練習のポイント」。
- これらはすべて既存の文言・ルール。日ごとの中身だけを撮影用パッチで用意した。

## 判断

- 撮影用パッチ `source/app-capture/month-days.patch`（3ファイル、アプリには入れない）：`--qa-mimi-day N` で、まとめの「今」を N−1 日先（N≥2 はその日の21:00、まとめはその日の20:00）にし、その日の例の日記とランキングを使う。
  - 1日目：日記1件（“And then” 1回、書き換え1件）、練習の /θ/。最初のレポート（`--qa-completed --qa-first-report`）。
  - 7日目：フィクスチャそのまま（“And then” 4回、“good” 3回、書き換え2件）、ランキング /θ/ 5・/l/ 3・単語の強勢 2。
  - 14日目：“And then” の代わりに After that / so / Later that day、“I think” 3回。/l/ 3・/θ/ 2。
  - 21日目：“very” 3回。/l/ 2。
  - 30日目：癖になる言い回しなし、ランキングなし →「目立つ癖はなかったよ」。
  例のデータなので、タイムラプスの間とコピーカードに「※画面は例として用意したサンプルデータ」と出した。
- 1回目の録画は、20:00前に撮ったため N 日目のまとめが前日の日付になった（7日目が10月26日）。パッチを「その日の21:00」にして録り直し（21:44に録画、時刻に左右されない）、1日目10月21日→7日目10月27日→…→30日目11月19日にそろえた。
- 1日目のフィクスチャの「デモデータ」の表示は、スクロールして見えなくなった後から使った（マスクなし）。
- ホラーの#24とは逆に明るく：双眼鏡で見張るMimi、メモを取るMimi（新しいポーズ2つ、`prompts/01-codex-poses.txt`）。オチは「見張ること、なくなった」（Mimiのせりふに一人称はなし。使うときは「僕」）。
- 英語の発音シーンがないので、オーナーの声（ownvoice.py）は使っていない。日本語のTTSも使わない。
- 音：声のない作品なので作品全体に1つのゲイン（−14 LUFS）＋ピークリミッター。

## 学んだこと

- まとめは「直近の締め時刻」で日付が決まる。日付を動かすフィクスチャは、録る時刻に左右されないよう「その日の締めの後」の時刻を指定する。
